# i18n — infrastructure only

*Not the te reo Māori interface. The plumbing it would need, proven against one page,
with the translated content deliberately left out.*

Code: `apps/web/src/i18n/request.ts`, `apps/web/src/lib/locale.ts`,
`apps/web/src/lib/locale.server.ts`, `apps/web/messages/`,
`apps/web/src/app/(app)/account/`.

---

## Why this stops well short of "the te reo Māori interface"

`docs/roadmap-phases-8-13.md` scopes that item honestly and the scope was taken at face
value: *"mechanical work touching every component in `apps/web` and `apps/mobile`, and it
is not a feature so much as a week of tedium plus an ongoing translation obligation on
every future string."* Doing that badly in one sitting — generating te reo Māori text for
every string across two apps with no way to verify it — would be worse than not doing it,
for the exact reason [[unverified-claims]] exists: this repo has already recorded one
macron mistake, caught only because somebody looked at the rendered page.

So this is the narrower, honest slice: the technical plumbing that any real translation
effort would need, built once and proven correct against a single real page, with the
translated content itself left explicitly as a placeholder. See unverified-claims item 34
for exactly what that means and what would close it.

## Why a cookie, not next-intl's own routing

next-intl's usual App Router setup puts the locale in the URL (`/en/...`, `/mi/...`) and
uses its own middleware to rewrite requests into that shape. This app's `middleware.ts`
already does one job that the whole security model depends on: it mints a fresh CSP nonce
on every request, which is what lets `script-src 'strict-dynamic'` hold instead of falling
back to `'unsafe-inline'` on a page where a guardian's phone number and a child's
anaphylaxis plan render. Composing a second middleware alongside that — or replacing it —
is a real way to break the nonce silently across every route at once, and the failure mode
would look identical to the one `apps/web/src/app/layout.tsx`'s own header comment already
records: a page that renders perfectly and executes no script the browser will run.

A cookie needs no middleware. `ece_locale` is read once, in `src/i18n/request.ts`, the same
shape `CENTRE_COOKIE` already uses in `@/lib/auth` for which centre is active — one more
small piece of state a browser carries, not a second control plane layered over the one
that already exists.

## Two files where the roadmap sketch expected one

`src/lib/locale.ts` holds pure constants — `LOCALES`, `Locale`, `LOCALE_LABELS` — and
`src/lib/locale.server.ts` holds `getLocale()`, which reads the cookie via `next/headers`.
Found by the build failing, not by reasoning about it first: `LocaleSwitcher.tsx` is a
Client Component that only needs the constants, but Next refuses to bundle *any* import
from a file that transitively pulls in a server-only API into client code — even an export
the client never touches. One file with both would have made every future page migration
hit the same wall.

## Two APIs for two component kinds, both exercised on one page

`/account/page.tsx` is a Server Component and calls `getTranslations()`, awaited. Its
child `ChangePasswordForm.tsx` is a Client Component (`'use client'`, it holds form state)
and calls the hook form, `useTranslations()`, un-awaited. `next-intl` requires the split —
the async server call cannot run inside a component that ships to the browser — and
migrating one page that exercises both was the point of choosing this one rather than a
purely server-rendered page, which would have left the harder half unproven.

## The `[mi]` prefix is the whole safeguard, and it is not enforced anywhere

`messages/mi.json` carries the same keys as `messages/en.json` with every value prefixed
`[mi] ` — `"[mi] Change password"`, not a translation. Selecting "Te reo Māori" in the
switcher on `/account` proves the mechanism works and shows exactly that it is not yet real
content. See unverified-claims item 34: nothing stops the prefix being stripped by someone
who mistakes it for a translation task already three-quarters done, and this page is one of
only two places that say not to.

## Verified

The build's own RSC boundary check caught the two-file split being necessary — a real
defect, not a hypothetical one, found the same session it was introduced. The cookie → 
`next-intl` config → rendered locale pipeline was checked end to end against the running
dev server on the unauthenticated `/login` page (every page shares the root layout): no
cookie and an explicit `en` both render `<html lang="en-NZ">`, `mi` renders
`<html lang="mi-NZ">`, and a garbage cookie value (`fr`) falls back to the default rather
than erroring. An authenticated check of `/account`'s actual translated strings was
attempted and abandoned — replicating Next's Server Actions POST protocol by hand through
curl is disproportionate effort for what the build and the RSC-boundary failure already
demonstrate is working; `next-intl` throws loudly on a missing key rather than rendering
silently wrong, and the message-file keys were written alongside the `t()` calls that use
them, not separately.

## What closing this properly means

Page by page, the same way the daily registers became three narrower wiki pages rather
than one: extract a page's strings, add them to both message files, translate `mi.json` for
real. Nothing here decides an ordering — `/account` was chosen because it is small and
exercises both component kinds, not because it is next.

## A macron changes how a string is stored, and how you can look for it

Hermes stores a pure-ASCII string one byte per character and switches the whole string to **UTF-16**
as soon as one character is not ASCII. So `Pānui` and `whānau` are simply not findable by an ASCII
`grep` of a shipped mobile bundle — the search returns zero, which reads as "not shipped".

Nothing about the app is wrong; the search is. It matters because inspecting the built bundle is how
every AAB in this repo has been signed off, and because the strings this page exists for are exactly
the ones that vanish. See [[mobile-app]], *Inspecting a build, and the grep that lies about te reo*.
